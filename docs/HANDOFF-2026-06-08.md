## ❌ TRIED & FAILED — do NOT repeat these

1. **Part-assembly / emitter port** (faithful per-part render). Blocked on the **LZSS shared scratch buffer**: MVC2 decompresses part textures into `0x0CE60000`; back-refs depend on prior parts' residue + a per-part size bound the static file lacks. Offline decode = noise; live capture from the scratch buffer = noise. Would need to hook the decompressor mid-frame. **Parked — whole-sprite makes it unnecessary.**
2. **Offline EXTRAS hotspot rip** (the `sprite_id → EXTRAS-assembly` index). Unsolved: the assumed field `keyframe+0x12` is actually **HitboxGroup**, not the assembly slot. The PL2A oracle is **non-discriminating** (all body poses ≈ `(-76,8)`, no object sprite to validate). EXTRAS *bytes* decode fine (`tools/rip_extras_hotspot.py --verify-pl2a`), but no sid→assembly map.
3. **PATH A — server-side `node+0x178` hotspot** (`?v=51`, server rebuilt, OBJS wire 9→11 B). **DEGENERATE, proven by `[OBJDIAG]`:** the `+0x178` walk returns a **constant per-character** hotspot = the **body's** value (Storm every object `hot=(-76,8)`, Ryu every object `hot=(-53,-17)`), or `hasHot=false` (Cable — no extras found). It cannot distinguish a projectile from the body. The wire change shipped but the client now **ignores** `hotDx/hotDy` (uses center). ⚠️ **OBJS wire is now 11 B/rec, OBJF 13 B/rec** — see "open" below.
4. **`+0xC8/+0xCC` object screen offset** — wrong (see #9 above). The real field is `+0xE0/+0xE4`.

**Root cause of all projectile-anchor attempts:** the bake (`bake.mjs:194`) anchors EVERY sprite — including projectiles — to the **body's** foot-origin (`dx = cropLeft − body.screen_x`). Correct for bodies, wrong for satellites (their own screen origin ≠ the body's). No runtime hotspot lookup fixes a bake-time error.
